# 内容后台：日常操作指南

打开本地后台 [管理工作台](http://localhost:3001/manage)。首次使用先在 `/admin` 创建管理员账号。

## 先认识首页

“工作台”集中页面与文章、产品、图片与文件、客户询盘、发布记录、自动翻译和站点信息。左侧“高级管理”默认折叠，里面是 SEO、导航、分类、发布任务路由等配置，不影响日常写内容。

## AI 写作草稿（V2.0 首批功能）

1. 管理员先在“自动翻译 → AI 设置 · DeepSeek”保存密钥并启用服务。AI 写作复用同一配置。
2. 从左侧“AI 写作”选择语言，填写文章主题。可选择该语言的现有产品，也可自行提供至少 20 字的事实资料；重点词语可选。
3. 点击“生成文章草稿”。结果会在右侧显示，直接修改标题、网址标识、导语、正文以及搜索标题和摘要。请核对所有技术参数、用途和表述。
4. 点击“保存为文章草稿”。系统会创建文章和 SEO 元数据，状态为草稿。随后到“页面与文章”列表打开该文章，复核后再点击“发布”。生成或保存草稿都不会自动上线。

如果提示网址重复，修改网址标识后重试。没有配置密钥时，生成按钮会停用并说明原因。

## AI Agent（V3.0 首批功能）

1. 管理员先在“自动翻译 → AI 设置 · DeepSeek”启用服务。后台左侧选择“AI Agent”，选页面、文章或产品，写明要改进的具体问题，并设置步骤与 token 上限。
2. 任务进入 Worker 队列。右侧按内容名称查看状态；打开任务可看模型计划、本站内容、SEO 检查及已有关键词/竞品/GEO 证据。可用数据为空时，Agent 不应编造事实。
3. 审核员或管理员检查逐字段的“当前 / 建议”对比，批准或驳回。批准后，有该内容编辑权限的人点击“套用到草稿”。若内容或 SEO 设置在运行后被别人修改，套用会被拒绝，需要重新创建任务。
4. 打开内容复核，再通过原有“检查 / 预览 → 发布”操作上线。Agent 不会自行发布、给客户发消息或调用任意网址。套用后可查看草稿 SEO 诊断分变化，并由发起人记录 1–5 分的人工效果评价；诊断分不等于流量或排名。

每天每人最多创建 10 次，预留总计最多 50,000 tokens；单次最多 8 步、2 次模型调用。任务失败仍会记录模型调用和已使用 token。详见 V3 AI Agent 本地升级记录（内部记录，不随公开仓库分发）。

## GEO 监测中心（V3.0）

1. 管理员打开“GEO 监测中心 → 模型与地区”，添加一个或多个兼容 Chat Completions JSON 接口的模型。填写模型名称、端点、密钥来源及供应商实际的输入/输出美元单价；价格不会自动获取。添加地区时，代码必须与该地区 Worker 的 `GEO_WORKER_REGION_CODE` 一致。
2. 在“总览与成本”设置日/月上限并启用预算。预算未启用时，任务会停在“预算阻止”，不会调用模型。页面会显示每个地区最近两分钟是否有 Worker 心跳。
3. 在“采样目标”保存固定问题，再选择问题、模型、地区和间隔。每个组合独立排队。可以手动采样一次，并在任务列表查看排队、完成、失败及估算费用。
4. 在“趋势比较”选择固定问题和 7/30/90 天窗口，比较各模型与地区的品牌提及率、每次样本的平均链接数、次数和估算费用。配置变化后的旧样本会从当前可比趋势中排除。

地区是 Worker 的**出站地区配置**，并未独立核验出口 IP 或模型服务端所在地区；市场标签不会让模型具备当地搜索定位。引用链接也未自动核实。原 V2.1 定时采样在升级时停用，需在监测中心建立带预算的新目标。详见 V3 GEO 监测升级记录（内部记录，不随公开仓库分发）。

## V2.0 日常工作流

- **内容检查**：选文章或产品，查看 SEO 诊断与修复入口、真实 HTML 草稿预览、公开版本差异。可填写定时发布时间；历史发布版本可生成回滚任务，当前编辑中的草稿不会被覆盖。发布与回滚都要在“发布记录”确认完成。
- **自动翻译 → 术语表 · 翻译记忆 · 批量校对**：先定义固定译法，再提交翻译；打开原文/译文对照，修改译文后标记已校对。已校对的句段进入翻译记忆；校对不会自动发布。
- **增长研究 → 关键词**：从 Search Console 导出包含 Query、Page、Clicks、Impressions、CTR、Position 的 CSV，输入报表日期及语言后导入。主题簇的点击和展示来自文件；“内容缺口”只作人工核对提示。站点属性需与“站点信息”一致。
- **增长研究 → 竞品观察**：输入指定的公开 HTTPS 页面，每页每小时最多采样一次。系统遵守 robots，只留标题、摘要、规范地址和标题层级快照。查看时间和变更时，不要把它当成完整爬虫或搜索排名数据。
- **增长研究 → GEO 监测**：设定固定问题、语言、市场标签和品牌，手动运行受控采样。原始回答、模型、用量、链接和品牌提及会保存。市场标签不是模型真实地理定位，链接也未独立核实。
- **客户跟进**：选询盘，更新状态、负责人、下次跟进时间并写备注。每次修改会留下审计记录；原始来源与 UTM 保留。
- **AI 助手**：选择一条文章或产品，以及写作、翻译或 SEO 任务。建议有模型和用量记录，但不会修改内容、发布页面或发送消息。

首次使用 V2.0 工作流前，需要管理员执行 `pnpm db:migrate` 应用 `014_v2_workflows.sql`。该操作应在对应环境按备份与发布流程执行。

## 发布一个页面或文章

1. 进入“页面与文章”，点击“新建页面 / 文章”。选语言与内容类型，填写标题和网址标识。网址标识只允许小写英文字母、数字和短横线；后台会预览完整路径。
2. 创建后在列表点“编辑”，填写摘要、正文区块，保存草稿。
3. 在对应记录点“发布”，再到“发布记录”确认任务已完成。保存草稿本身不会更新公开网页。
4. 要增加另一种语言，在该记录点“添加语言”。新版本会关联同一个内容主体，无须复制任何编号。翻译人员也可执行此操作。

## 上架一个产品

1. 进入“产品”，点“新建产品”。填写 SKU、名称、语言、网址标识。
2. 点“编辑”填写简介、详细介绍、产品特点和应用领域。特点及应用领域每行一条。
3. 点“产品图片”，在图片库按文件名搜索，选择图片并添加。第一张是封面；可随时设为封面或移除。图片修改后重新发布产品。
4. 在记录上点“发布”，到“发布记录”确认完成。其他语言在产品记录上点“添加语言”创建。

## 图片、询盘和网站设置

- **图片与文件**：上传素材；图片行的“图片描述”可填写各语言 ALT。描述图片中实际看得到的内容。
- **客户询盘**：打开记录查看客户留言，修改状态和负责人。新询盘会自动列出。
- **站点信息**：维护网站名、域名、联系方式和搜索引擎收录开关。
- **发布记录**：失败时打开任务查看原因，修复后重试。

## 保存之后怎样才能在公开站点看到

后台会按资源类型给出不同的保存提示和按钮，规则只有一条：

- **单条发布**（页面 / 文章、产品的各语言版本、分类翻译）：保存后在记录行点“发布”，只更新这一条记录。
- **全站重建**（站点信息、站点翻译、导航菜单与导航项、首页轮播与轮播翻译、客服渠道与规则、语言）：这些内容会被写进**每一张**已发布页面，所以保存后要在当前页面的工具栏点“重新生成已发布页面”，或到工作台点同名按钮。只保存不重建，前台不会有任何变化 —— 这是最常见的“改了没生效”的原因。
- 其它记录（询盘、媒体库、SEO 元数据等）不参与发布流程，保存即入库。

## 什么时候打开“高级管理”

需要配置分类、菜单、首页轮播、客服规则、SEO/GEO、301 跳转、结构化数据或系统权限时再展开。这里的部分页面保留技术字段，适合管理员操作。

## DeepSeek 自动翻译与 AI 设置

1. 管理员进入“自动翻译”，展开“AI 设置 · DeepSeek”。模型默认 `deepseek-flash`，接口默认 `https://api.deepseek.com/chat/completions`。密钥加密（AES-256-GCM）保存在数据库中，保存后不会回显，也不会写入日志或审计记录；请妥善保管服务器的 `PAYLOAD_SECRET`，更换它会使旧密钥无法解密（此时页面会提示重新填写）。
2. **测试连接**可以直接用刚填、还没保存的密钥试跑，不需要先保存；测试只发一次真实请求，不会改动已保存的配置。按钮只在“既没有已保存密钥、也没填新密钥”时禁用。测试成功会显示模型、耗时、token 用量和一段`返回样例`；失败会给出可执行的原因（密钥无效 / 余额不足 / 模型不存在 / 限流 / 超时 / 无法出网）。
3. 保存语义：密钥栏留空＝保留已保存的密钥；填入新值＝替换；勾选“删除已保存的密钥”后需要再点一次“确认删除并保存”才生效。密钥来源与指纹会显示在表单下方，方便确认当前生效的是哪一把密钥。
4. 在“页面与文章”或“产品”列表找到原文，点“自动翻译”，选择目标语言，可一次提交多个任务。已有草稿需要勾选允许覆盖；已发布版本不能被任务覆盖。
5. 进入“自动翻译”查看等待、翻译中、待校对或失败状态。失败任务可重试。点“查看译文草稿”人工校对，然后在内容列表单独发布。机器翻译不会自动公开。
6. 页面标题、摘要、正文区块，以及产品名称、介绍、特点和应用领域会翻译；链接、图片地址、SKU 和技术数值保留。长内容超出单次上限时需拆分；译文被上游截断或漏段时任务会判失败并要求重试，不会写入不完整的译文。

可选：服务器环境变量 `TRANSLATION_API_KEY`、`TRANSLATION_MODEL`、`TRANSLATION_API_URL` 可提供初始值。后台保存的密钥优先于环境变量；设置页可以停用翻译。配置由 CMS 和 Worker 从数据库读取，无须在两处重复填写。

## V2.1 协作与增长（本地升级）

在左侧打开“协作与增长”。“团队任务”可从页面、文章和产品中按名称选择最多 30 条，指定负责人、截止时间和说明；负责人将任务送审，审核员确认完成。新增或修改的翻译术语先进入待审批，批准后才用于后续翻译。已有已批准术语在升级时保持批准状态。

“变化与趋势”显示竞品公开页面的标题等结构变化。点击“已查看”仅关闭提醒；内链和内容更新建议须由编辑核对。GEO 重复采样由 Worker 执行，可按小时、天或周安排；需要先在“增长研究”创建问题，并配置可用的 AI 服务。趋势只比较相同配置的样本。

“合作外联”记录合作对象、联系草稿、人工审批、实际回复和链接。系统不发送邮件；“我已在外部人工发送”只记录操作。新记录的链接标记为未核验。

“CRM 同步”由管理员填写通用 HTTPS CRM 根地址和访问令牌。启用后 Worker 会拉取远端线索并推送本地询盘，字段包含客户姓名、邮箱、公司、电话、留言与状态。先核对接口契约与本地升级步骤（不随公开仓库分发），再启用。发生冲突时后台显示本地与 CRM 信息，管理员选择保留本地或采用 CRM 记录；失败任务可重试。令牌不会回显，依赖 `PAYLOAD_SECRET` 加密，密钥变更后需重新填写。未配置真实 CRM 时不要开启同步。
## V3.0 客户与商机、营销、经营报表

“客户与商机”统一管理询盘线索、客户公司、联系人、销售机会、负责人、协作成员、沟通记录和跟进任务。原有询盘会按邮箱关联联系人、按公司和地区关联客户；后续新询盘同样自动关联。销售阶段为新机会、确认需求、方案/报价、商务洽谈、成交、未成交；丢单须填写原因。客户档案的时间线保留既有询盘和跟进备注，也记录商机、任务与沟通。外部 CRM 双向同步仍使用 V2.1 的通用 HTTPS 询盘接口，位于该工作台“外部同步”页。

“营销自动化”需要单独登记营销同意及来源证明。提交询盘时勾选的隐私同意不等于营销订阅。先创建分群和活动草稿；管理员确认发送接口、退订密钥、HTTPS 站点地址和全局频率上限后启用总开关，再审核并启用活动。手动活动对当前匹配者排队，触发活动只处理启用后的新询盘或销售阶段变更。退订后取消待发送任务；每次实际发送前还会复查同意与频率。发送方须提供幂等 HTTPS JSON 投递接口，具体契约见 [API 文档](API.md)。

“经营报表”仅管理员可见。选择 UTC 日期范围生成快照，查看询盘、商机、营销、GEO、跟进任务和发布指标；点击每个数值可查看当时计入的原始记录及每日趋势，可对比历史报告或导出 CSV。报告中的“当前有效询盘”“开放商机”是生成时的状态快照；金额按原币种分开，不自动换汇。定义与限制见 本地升级记录（内部记录，不随公开仓库分发）。
# V3.1 外贸官网与询价

1. 在「首页轮播」及「轮播翻译」上传真实产品/工厂素材，并按语言填写标题与按钮；发布产品、案例与文章后，在「发布记录」执行全站重建。自动首页会展示已发布内容；没有案例时不会显示空案例区。
2. 在「产品」列表点击某条产品的「采购资料」，填写共用的起订量和参考交期，以及当前语言的订购单位、包装、定制、样品政策。规格、图库和资料下载仍由对应的产品结构功能维护。只填写已核实的内容。
3. 保存采购资料后，逐一重新发布该产品已启用的语言版本；更改共享字段时尤其要注意各语言快照。
4. 访客在产品页点击「加入询价」；联系页会带出当前浏览器、当前语言的询价清单，可改数量、移除产品并填写目的地、期望日期、贸易条款、规格备注及一份 PDF/图片附件（上限 5 MB）。提交后在「客户与商机」→「询盘线索」查看每项产品和私有附件。
5. 附件只有具备询盘读取权限的登录用户可以下载。询盘同意不等于营销订阅同意。

本地升级和后续报价规划见内部升级记录（不随公开仓库分发）。

## 外贸业务（V3.2–V3.4）

后台进入“外贸业务”，按顶部五个标签操作：获客漏斗、报价协作、市场化内容、采购信任与服务、客户与渠道入口。

- 报价从 RFQ 产品清单创建，保存为独立版本，提交另一位审核员审批，然后发出到客户入口。
- 邀请由操作员核对邮箱后手动发送；客户可确认报价，渠道邀请只读。支持期限和撤销。
- 市场卡片关联真实已发布页面或公开证明，审核后在官网首页展示。失效和来源变更会停止公开返回。
- 服务时限对新询盘生效；人工回复后记录渠道和内容。
- 漏斗按询盘创建日期统计并追溯，访问会话只包含明确同意的访客。

数据库须应用 023 迁移。完整操作步骤、权限和回退说明见 外贸业务升级记录（内部记录，不随公开仓库分发）。
