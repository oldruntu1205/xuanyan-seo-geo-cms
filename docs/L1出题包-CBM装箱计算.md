## 3. 请 L1 特别注意的三点

1. **A7 是最有价值的一条**：它保护的是一个**会静默少算一整箱**的缺陷，而且这个缺陷在 22080 个现实组合里只出现 21 次（实测数据见 §4）。删掉 1e-9 容差后，绝大多数用例仍然绿 —— 所以必须把那个具体组合写死。
2. **A10/A11 是"防猜测"**：半截箱规如果被容错成"能算就算"，会产出看起来专业、实际错误的 CBM 进入报价。宁可不出数字。
3. **A9 是防止测试变脆**：容器常量属于业务口径（会随船公司/航线调），不要写成"33.2 是正确的"这种测试；要用 A4/A5/A7 的硬编码数字去**暴露口径变更**，而不是阻止它。

### 4.0 浏览器验收中发现的非缺陷观察（诚实记录，未改代码）

箱规输入框回填时显示的是 pg 的原始 numeric 字符串（`12.000`、`500.0`），而不是 `12`、`500`。**这不是本次引入的**：同一对话框里既有的「起订量（MOQ）」字段走的是同一条 `row.x ?? ''` 代码路径，验收脚本里把 MOQ 一起填成 100 后，它同样显示 `100.000`（探针产品本机库里 MOQ 全为 NULL，故特意造了这个对照）。

- 影响：纯显示观感，数值正确、保存与计算都不受影响。
- 决定：**本轮不改**（保持与既有一致；单改箱规会造成同一对话框内两种形态并存）。若要统一，建议单独一次改动把该对话框所有数值字段一起规范化。

### 5.5 真库测试的事务纪律（L1 指定，L2 按此实现）

预期失败的 CHECK 用例必须逐个包在 `SAVEPOINT` 里 —— PostgreSQL 一旦 CHECK violation，当前事务进入 aborted 状态，不隔离就会让后续用例无法执行：

```text
BEGIN
  SAVEPOINT case_a14_1 → 非法写入 → 期望 23514 → ROLLBACK TO SAVEPOINT case_a14_1
  SAVEPOINT case_a14_2 → ...
  合法形态 / A17 正常插入与查询
ROLLBACK
最后事务外再查一次探针 SKU 数量 = 0   ← 「夹具自清」本身也成为可验证的不变量
```
