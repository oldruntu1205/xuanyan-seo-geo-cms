# V2.0 全量落盘实施计划

基线：项目根目录《产品线路图.md》，现有 PostgreSQL/Payload/Next.js 架构，2026-09-27 当前未提交的 AI 写作首版。所有功能沿用 `packages/domain` 业务层、`apps/cms` 鉴权 API 与 `/manage` 工作台；公开站点只读已发布快照。

## 范围与验收

1. 翻译：术语表、翻译记忆、原文/译文对照、批量审核和单项重试；审核不能直接发布。
2. SEO：对草稿和产品提供可解释的逐项诊断，含标题/摘要、canonical、hreflang、结构化数据、内链、图片 ALT、索引状态与修复入口。
3. 发布：真实 HTML 草稿预览、当前公开版差异、后台定时发布、失败重试、已发布快照回滚及审计。
4. 关键词：导入自有 Search Console CSV，保存站点/语言/时间范围/来源，做可追溯聚类与内容缺口建议；不虚构搜索量。
5. 竞品：只采集运营指定的 HTTPS 公开 URL，遵守 robots、限制速率和响应大小，留来源/时间并比较标题与主题；不复制正文。
6. GEO：固定提示词、模型/市场/语言、手动受控抽样、原始回答、品牌提及与引用链接的时间记录；明确是样本而非全网排名。
7. 轻 CRM：询盘状态、负责人、跟进备注、下次跟进时间和来源，带权限与审计。
8. 受控 AI 助手：对当前文章、产品或 SEO 诊断提出建议；只读限定资源，输出建议，不自动写入、发布或外发；记录模型、耗时和用量。
9. AI 写作/后台：补调用指标和事实来源记录；功能入口采用名称与任务流程，保留高级配置但减少原始编号展示。

## 设计边界

- 关键词第一版接受 Search Console CSV 导入，避免引入尚未配置的 OAuth 凭据。文件格式明确校验，原始计数和时间范围不丢失。
- 竞品抓取限定管理员/SEO 经理手动触发、HTTPS、公共 DNS 地址、robots 放行及请求频控；不抓取搜索引擎结果页。
- GEO 采样使用已配置的 DeepSeek 服务；地区字段是运营设定的实验标签，不宣称能模拟真实地理定位。
- 发布回滚复用已经完成的 `publish_jobs.metadata.snapshot`，生成新的发布任务；不覆盖编辑中的草稿。新旧来源保持单一。
- 新持久化结构只进新的 014 迁移及对应 rollback，不修改历史迁移。新增业务权限沿用现有 `content/seo/translation/leads/publishing`，AI 配置仍仅管理员可见。
- 自动外链不纳入批量发布链接；路线图中的合规外联留在 V2.1。

## 实施顺序

1. 锁定当前数据结构、权限与 API 入口；新增 V2 迁移与 rollback。
2. 域层实现 SEO 诊断与发布预览/差异/回滚，再接 API 和后台。
3. 实现翻译术语/记忆和审核；补 AI 写作来源及用量。
4. 实现关键词 CSV 导入/聚类，竞品受限采集与差异，GEO 受控采样。
5. 实现询盘跟进和受控 AI 助手。
6. 整合后台任务入口、空状态、错误说明，更新管理员指南/API/路线图状态。

## 变更必要性与兼容性

现有字段无法保存关键词来源、竞品快照、GEO 实验结果、翻译记忆和询盘跟进，因此需要新迁移及域 API。现有发布任务和内容版本要复用；保留 V1 公共 API、静态路由和翻译任务接口。回滚脚本只回退本次新增结构，禁止对现有业务数据作删除式重建。
