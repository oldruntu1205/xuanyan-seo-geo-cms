## 本地迁移

在项目根目录的 PowerShell 中执行：

```powershell
$env:DATABASE_URL=(Get-Content -LiteralPath '.runtime/connection.json' -Raw | ConvertFrom-Json).DATABASE_URL
node infrastructure/scripts/migrate.mjs status
node infrastructure/scripts/migrate.mjs up
```

若演示数据库已启动且 015 标记为 `true`，无需重复迁移。独立安装请使用其实际 `DATABASE_URL`；先备份数据。回滚脚本 `database/rollback/015_v21_collaboration.down.sql` 会删除 V2.1 协作、外联、CRM 记录和 GEO 配置快照字段，不能作为无损撤销。

## 后台流程

1. 在“自动翻译”维护术语；审核员在“协作与增长 → 团队任务”批准后，新翻译任务才会使用它。批量任务选择内容名称、负责人和截止时间；负责人提交审核，审核员确认完成。
2. 先在“增长研究”采样竞品公开页面、保存 GEO 问题；再到“变化与趋势”查看提醒、安排重复采样。市场是实验标签，不代表模型实际地理位置；引用链接是模型输出，未独立核验。
3. 在“合作外联”研究对象并编写草稿。审核通过后由人从外部渠道发送，再手动记录发送、回复和获得的链接。系统没有发送动作。
4. 管理员在“CRM 同步”保存根地址与令牌，再启用。冲突列表会并排显示本地和远端字段；没有匹配记录时可选择本地询盘或作为新询盘导入。失败任务可以手动重试；冲突任务须先处理。

## 通用 HTTPS CRM 协议

根地址示例为 `https://crm.example.com/api/`。服务只接受公开 HTTPS 域名与标准 443 端口；每次请求重新解析并固定公开 IP，不跟随重定向。请求带 `Authorization: Bearer <token>`、`Accept: application/json` 和 `Content-Type: application/json`。单次请求超时 15 秒，响应上限 1 MB。

### 拉取

`GET <根地址>/leads?limit=100`；后续页增加 `cursor=<上页 nextCursor>`。响应：

```json
{
  "items": [{
    "externalId": "crm-lead-42",
    "externalKey": "可选的本地询盘 UUID",
    "name": "Example Contact",
    "email": "contact@example.com",
    "company": "Example Ltd",
    "phone": "+1 555 0100",
    "message": "Interested in a quote",
    "status": "new",
    "updatedAt": "2026-09-27T08:00:00Z"
  }],
  "nextCursor": "下一页游标，最后一页为空字符串"
}
```

`externalId`、有效邮箱、名称和可解析的 `updatedAt` 必填。状态只识别 `new`、`processing`、`qualified`、`replied`、`closed`、`spam`；其他值回落为 `new`。一次任务最多处理 10 页，每页最多 100 条。远端应提供稳定游标；超过上限会以失败状态提示处理范围过大，已处理页面不会自动回滚。

### 推送

`POST <根地址>/leads/upsert`。请求体包含 `externalKey`（本地询盘 UUID）、已有映射时的 `externalId`，以及 `name`、`email`、`company`、`phone`、`message`、`status`、`updatedAt`、`createdAt`。远端应以 `externalKey` 幂等 upsert，成功返回 JSON：

```json
{"externalId":"crm-lead-42","updatedAt":"2026-09-27T08:00:00Z"}
```

远端发现并发冲突时可返回 HTTP 409，JSON 体须为 `{ "record": <上述完整远端线索对象> }`。其他非 2xx 响应进入失败重试，最多 5 次，延迟逐步增加；到上限后由人工重试。不要将令牌或客户原始消息放入 HTTP 错误描述。

### 匹配与冲突

- 优先使用已有 `externalId` 映射；随后识别合法的 `externalKey`；再用邮箱及公司匹配。含糊匹配、单个未确认匹配和双方同时更新会进入冲突列表。
- 管理员“保留本地并推送”将本地记录再次提交；“采用 CRM 记录”会覆盖匹配记录，或按选择导入新询盘。选择现有记录时，邮箱及公司必须相同且它不能关联另一条 CRM 记录。
- 开放的冲突不会被后台自动覆盖；重复拉取不再生成同一外部记录的重复冲突。同步关联、任务状态和人工处理结果留在数据库及审计记录中。
- CRM 令牌由 `PAYLOAD_SECRET` 派生密钥做 AES-256-GCM 加密，保存后不回显。更换 `PAYLOAD_SECRET` 会使旧令牌无法解密，需要重新录入。
