## 执行边界

1. Agent 仅处理一个已存在的页面、文章或产品语言版本。计划最多 8 步，其中最后一步是方案。工具白名单为当前内容、SEO 检查、已有 Search Console CSV 关键词数据、已有竞品快照、已有 GEO 样本。没有任意 URL、SQL、Shell、外发邮件或发布工具。
2. 一次任务最多 2 次模型调用（计划、方案）；后台单次 token 预算 5,000–16,000，默认 8,000；每人 UTC 日最多 10 次、预留总预算最多 50,000。模型调用记录实际 usage；供应商缺失 usage 时采用保守估算。失败任务也占用当日预留额度，避免反复请求产生费用。
3. 模型输出经固定 JSON 结构校验，只允许修改标题/名称、摘要/简介、产品详细介绍及 SEO 标题/摘要。SEO 设置采用复制后关联到当前内容的方式，避免修改共享记录。所有修改通过审核后才进入草稿，并有审计和内容版本；内容或 SEO 自创建任务后发生变化会拒绝套用。
4. 只有审核/发布权限者可批准或驳回；有内容写权限者可套用；公开发布必须再走原有人工发布流程。任务发起人可打分并写效果备注。草稿 SEO 诊断分的前后变化仅是内容质量提示，不代表自然流量、排名或实际询盘变化。

## 本地升级

本地数据库已应用 `016_ai_agent.sql`。若在另一套本地环境升级，先备份数据库，再按既有迁移命令运行 `node infrastructure/scripts/migrate.mjs up`；重启 CMS 和 Worker 进程以加载新代码。管理员需在后台“自动翻译 → AI 设置”配置可用 DeepSeek 模型与密钥。无需在仓库或聊天中写入密钥。

回滚脚本会删除 Agent 任务、步骤与决策数据。正式回滚前应导出需要保留的记录。
