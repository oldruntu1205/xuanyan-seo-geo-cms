## CRM 数据与协作口径

- 询盘仍是原始线索。客户联系人按不区分大小写的邮箱归并；客户公司按标准化名称及地区归并。同一邮箱可关联多个客户公司；销售机会始终指向一个联系人，可关联公司与原始询盘。
- 销售阶段：`new → qualified → proposal → negotiation → won/lost`。可回退阶段，所有阶段、负责人及任务变化写入客户历史和审计；丢单要求原因。编辑商机使用更新时间检查，避免覆盖同事刚保存的改动。
- 商机负责人或管理员调整协作成员；任务执行人、创建人或管理员可更新任务。沟通记录支持备注、电话、邮件和会议。归档联系人不会删除已有询盘与历史。
- 既有通用 HTTPS CRM 适配器继续同步询盘级资料，不将内部商机、协作成员、营销同意或历史自动推到外部 CRM，避免扩展外部接口契约时意外泄露。

## 营销发送边界

- `inquiries.consent_at` 是提交询盘时的隐私处理同意，**不作为营销授权**。营销订阅只由 `marketing_consents.state='granted'` 且具备同意来源、证明与时间的记录决定；本次没有把旧询盘批量转为订阅者。
- 管理员需先在环境中设置 `MARKETING_UNSUBSCRIBE_SECRET`（至少 32 字符）、`MARKETING_DELIVERY_URL`（公开 HTTPS JSON 接口）、`MARKETING_DELIVERY_TOKEN` 与 HTTPS 的 `NEXT_PUBLIC_SITE_URL`。新安装由 `pnpm setup` 生成退订密钥。仅配置密钥不会触发发送；总开关默认关闭，活动初始为草稿。
- 发送服务契约：`POST` JSON `{to,subject,text,unsubscribeUrl,headers,metadata}`；鉴权 `Authorization: Bearer ...`，幂等键 `Idempotency-Key`。服务商应透传 `List-Unsubscribe` 与 `List-Unsubscribe-Post` 到最终邮件，并保证相同幂等键不会重复投递。系统仅把服务商 2xx 视为“已接收”，不推断收件箱到达或打开。
- 每次领取任务时，在数据库锁下再次核对联系人状态、明确同意、同联系人正在发送的任务、最近 7/30 天上限、同活动冷却期、活动每日上限和全局每日上限。退订会撤销同意并跳过待发送任务。已交给供应商的在途邮件无法撤回。
- 失败按延迟重试最多三次；Worker 中断的发送依赖供应商幂等键防止重复。管理员应在上线前核验供应商的幂等和退订头支持，并用真实邮箱进行业务验收。所有营销收件人为明确同意的联系人；没有默认群发。

## BI 统一指标（定义版本 1）

| 指标 | 口径 |
| --- | --- |
| 收到询盘、当前有效询盘 | 按询盘创建时间；“有效”取报表生成时的当前状态。 |
| 新增商机、当前开放商机 | 按商机创建时间；开放阶段取报表生成时的当前阶段。 |
| 成交商机、成交金额 | 按商机关闭时间；仅当前处于 `won` 的记录。金额按币种拆分，不换汇。 |
| 营销发送、营销退订 | 发送服务返回 2xx 的记录；已同意转为退订的事件。 |
| GEO 模型估算成本 | 新 GEO 采样的记录成本；为估算美元支出，需与供应商账单对账。 |
| 完成跟进任务、完成发布任务 | 分别按任务完成时间和发布任务完成时间。 |

报告以 UTC 日历日过滤。在同一个 PostgreSQL `REPEATABLE READ` 事务内保存指标定义、来源记录及汇总，生成后不随源记录修改而改变。每个指标可下钻到当时计入的记录，CSV 包含来源表、编号、名称、时间与计入值。单次最多 367 天、10 万条指标来源记录；较大范围分段生成。报表仅管理员可见。CSV 对以公式符号开头的名称加前缀，降低电子表格公式注入风险。
