## 本地配置与使用

1. 本地演示数据库已执行 `017_geo_monitoring.sql` 与 `018_geo_scale_indexes.sql`。其他环境按迁移顺序备份后运行 `node infrastructure/scripts/migrate.mjs up`，再重启 CMS 与 Worker。
2. `.env.example` 与新 `pnpm setup` 已支持 `GEO_MONITOR_SECRET`。本地现有 `.env` 已补入独立随机密钥；不要将它提交到 Git。CMS 与处理专用模型的地区 Worker 必须使用同一个值。
3. 管理员在后台配置模型端点与密钥、单价、地区；在“总览与成本”设置上限并启用预算。复用站点密钥的模型只能使用站点 AI 设置中相同的端点。供应商专用模型需单独输入密钥。
4. 创建固定问题及“问题 × 模型 × 地区”目标，启用后按间隔调度，也可手动提交一次。预算不足或关闭时任务显示“预算阻止”，不会调用模型；调整预算后需重新提交任务。
5. 默认只有代码为 `local` 的地区，代表当前主 Worker 的出站网络。新增其他地区后，需要把专用 Worker 部署到实际目标地区，并配置 `DATABASE_URL`、`GEO_WORKER_REGION_CODE`、`GEO_WORKER_ID` 和 `GEO_MONITOR_SECRET`；若复用后台保存的站点密钥，还需相同的 `PAYLOAD_SECRET`。在该主机的项目中运行 `pnpm --filter @suns/worker geo-region`。此入口只执行 GEO 任务，不运行发布、CRM 或翻译。

## 统计与成本口径

- 地区取自执行任务的 Worker 配置和在线心跳，未做出口 IP 的第三方核验；只能代表声明的请求出站位置。模型服务端位置和搜索引擎的本地化结果不在本轮验证范围。
- `market` 仍是问题的市场标签，不是地理定位指令。固定问题的回答是模型采样，不等同于 Google 搜索结果或真实 AI 搜索曝光。
- 品牌提及率为答案文本包含品牌名称的次数 / 样本数；“平均链接/次”为模型返回的 HTTPS 链接条数 / 样本数。链接未独立核验，多个链接会使该平均值大于 1。
- 配置指纹包含问题、市场标签、品牌、语言、模型、端点、模型配置 ID 和地区；变化前后的样本不混入当前趋势。旧版无地区/价格数据的样本不计入新趋势与预算。
- 成本使用管理员录入的 USD 单价与供应商 token 用量估算；未包含缓存折扣、税费、汇率、供应商特定计价项，必须与供应商账单核对。调用前按最多 4,000 输入 tokens 加模型最大输出 tokens 预留；若实际用量高于预留，已发生的单次费用可能使预算略微超出。
- 日/月窗口均按 UTC。任务失败或 Worker 中断可能已在供应商侧计费，却没有完整响应 token 用量；后台明确记录失败，需对账。

## 兼容与限制

- 017 迁移会暂停旧 `geo_sampling_schedules` 中启用的计划，防止旧 Worker 绕过新预算。旧手动采样接口只会将一个已启用的本地目标加入新队列；旧定时接口返回引导信息。历史 `geo_samples` 保留，旧版趋势仍可查历史。
- 单个地区 Worker 每次最多 8 个并发采样；主 Worker 每 4 秒领取 1 个本地任务。总吞吐需按实际供应商限流和预算设置。调度器每轮最多处理 100 个到期目标，避免瞬时压垮队列。
- 仅支持提供兼容 JSON Chat Completions 接口的模型；不内置浏览器搜索、实时联网检索或搜索结果页采集。
