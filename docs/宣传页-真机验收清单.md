## 0. 怎么把页面拿到手机上（三选一）

| 方式 | 步骤 | 适用 |
| --- | --- | --- |
| **A. 随站点发布**（推荐，最接近真实） | 由项目所有者把该 HTML 放进 `static-site/`（或 nginx 站点目录）→ 手机访问对应 URL | 需要走一次部署；以后改动同步 |
| B. 本机局域网 | 本机起静态服务（`node .runtime/promo-static-server.mjs 玄砚企业智慧营销CMS系统-交互宣传页.html`，监听 8899）→ 手机与电脑同 WiFi 访问 `http://<电脑局域网IP>:8899/` | 快速试；需把服务绑定到 `0.0.0.0` 而不是 `127.0.0.1` |
| C. 传文件 | 把 HTML 发到手机（AirDrop / 网盘）→ 用「文件」App 或 Safari 打开本地文件 | 最快；但 `file://` 下部分浏览器行为与线上不同（**结论仅供参考**） |

> ⚠️ 页面有 **1 个外链 `<link href>`**（在线资源）。用 C 方式且无网络时该资源会加载失败，属于预期，不代表线上问题。

## 1. 必查项（按重要性排序）

- [ ] **顶部导航与汉堡菜单**：竖屏首屏能看到菜单按钮；点开后菜单展开（自动化已验：`display: none → flex`，高度 211px）；**再点一次能收起来**；菜单展开时**不能遮住或错位**正文。
- [ ] **点击热区**（本次自动化的主要风险点）：页面共 **58 个可点元素**，其中 **25 个高度 < 32px**。请在真机上逐个试：步骤标签（`01 企业营销 CMS` … `12 客户与渠道入口`）、`下一步`、`重置`、`推进到下一状态`。iOS 建议热区 ≥44px，**手指点不中就是必须修的缺陷**。
- [ ] **无横向滚动**：任何区块左右滑动都不应带动整页横移（自动化在 390×844 下 `scrollWidth == innerWidth`，真机需复核，尤其字体放大后）。
- [ ] **五步工作流**：点任意步骤标签 → 标题/描述/标签跟着换；点「下一步」→ 步骤推进（如 `03 / 05 · DISCOVER` → `04 / 05 · CONVERT`），走到第 5 步后行为合理（不能点出界）。
- [ ] **十二个功能区演示**：逐个点，每次都应更新**中间画布**、**面包屑**与**选中态**；特别注意 `04 AI 与静态发布`、`07 企业官网与 RFQ`、`09 报价协作` 这几个含子交互的（画布内还有「推进到下一状态 / 重置」）。
- [ ] **搜索 / 语言切换 / 发布 / CRM 四个内嵌演示**：都能点、状态有反馈、不报错。
- [ ] **表单类输入**（若有）：能唤起 iOS 键盘、输入不跳版、失焦后布局不塌。
- [ ] **旋转屏幕**：竖 → 横 → 竖，导航与画布都要重新排好，不出现内容被裁切。
- [ ] **Safari 特性**：地址栏收起/展开时，吸顶导航与 `100vh` 区块不应跳动或出现空白条。
- [ ] **性能与手感**：滚动是否跟手（无明显掉帧）、动画是否卡顿；页面 238 KB 单文件，Weak 网络下首屏可接受。
- [ ] **深色模式**（若系统开了）：文字与背景对比度够不够，有没有看不清的区块。
- [ ] **无障碍抽查**：开 VoiceOver，菜单按钮是否读作可展开/已展开（自动化看到 `aria-expanded=true` 已正确切换）。
