## 已知问题（本次实测，**已修复并部署**）

`D222450` 的**葡萄牙语**任务曾连续 **4 次**失败，错误固定为：

```text
译文达到长度上限被截断，请减少一次翻译的内容后重试
```

**根因**（读代码定位）：[`packages/domain/src/llm.ts`](../packages/domain/src/llm.ts) 的 `llmTranslateBatch` 对 `finish_reason === 'length'` 直接判失败，而该批用的是 `callLLMChat` 的默认 `max_tokens: 4096`。该批中文仅 ~400 字符，**是模型输出失控跑满上限**，不是输入太长。

**修法（已实现）**：`finish_reason==='length'` 时**把多段批对半再切、递归重试**，结果按原顺序拼接、用量累加；**单段批仍显式失败**（文案不变），保住"缺段即失败、不静默丢弃"的契约。

**验证（命令级）**：

- `pnpm -r typecheck` exit 0；`pnpm test` **17/17**（`tests/llm.test.ts` 的单段截断用例语义不变，未改测试）
- **本地端到端**：用「多段批必被截断」的假 LLM 跑真实翻译任务，请求序列 `7 → 4/3 → 2/2/2/1 …` 共 13 次、7 个叶子全部成功，任务终态 **`review`**（修复前 `failed`）
- **生产**：修复部署后重跑该条 → `status=review`（一次通过），7 语言草稿各 3 条 = **21/21**，失败任务 **0**

## 发布前必查（判定 SQL）

发布后每个语言应满足「可作为询价产品的已发布译文数 ≥ 1」，判定同 [`apps/cms/src/server/api.ts:73`](../apps/cms/src/server/api.ts#L73)：

```sql
SELECT l.code, count(*) FROM locales l
LEFT JOIN product_translations t ON t.locale_id = l.id
LEFT JOIN published_documents d ON d.entity_id = t.id AND d.entity_type = 'product_translations'
WHERE l.is_enabled GROUP BY l.code ORDER BY l.code;
```

## 通过后怎么发布（不要手改数据库）

1. 逐语言在 `/manage` → 产品译文里核对（也可直接改文字后再保存）；
2. 确认无误后在服务器跑 `/tmp/publish-translations.sh`（**带占位文案闸门**，命中占位句会中止，除非显式 `FORCE=1`）；
3. 脚本会逐语言发布 → 等发布任务 → 全站重建 → 逐语言公网核验，并打印已发布快照数；
4. 回滚：对相应译文 `unpublish` 后重建全站，或用 `/root/suns-backups/static-site_*.tar.gz` 覆盖产物。
